## Corrective plan

`MASTER_PLANv2.md` now makes the omitted requirements explicit as 27.11--27.16,
29.7--29.8, and 30.6--30.9. Phase 30.1 and 30.5 are reopened because their
wording requires composition and product controls, while the evidence proves
only a state contract and projection.

Implementation should proceed in this order:

1. Define the new versioned lifecycle contracts and strict schemas without
   granting runtime effect.
2. Add replaceable unprivileged adapters and deterministic privileged brokers
   only where host effects require them.
3. Implement cancellation, stale-state, partial-failure, restart, replay,
   revocation, audit, postcondition, and rollback tests for every mutation.
4. Compose all engineering services behind Core admission and expose truthful
   Console/Shell controls.
5. Rebuild a signed candidate and run installed scenario, lifecycle, hardware,
   fresh-user, update/rollback/repair/removal, and adversarial matrices.
6. Load `fam-os-userns` through owner authentication, pass clean physical
   preflight, run the final-candidate 24-hour soak, and obtain independent human
   review.
7. Update integration coverage only from the resulting aggregate installed
   evidence.
